# Test case catalogue

Every test in the suite: what it checks, where its expected behaviour comes from, and how it is built. The app under
test, [redux-athena-bank](https://github.com/Zetyre/redux-athena-bank), is a training mock with no specification,
so the source of each expectation matters as much as the check itself.

79 test cases, 97 tests, 179 runs per full run: 56 API tests, and 41 UI tests in Chromium, Firefox and WebKit. A test case (`TC-0xx`) can hold several tests when the same
check runs on several inputs (for example TC-021 checks each of the four required sign-up fields).

## How the project fits together

| --------------------- | ------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Projects              | [`playwright.config.ts`](../playwright.config.ts)                                                | `api` runs `tests/api` with no browser. `chromium`, `firefox`, `webkit` run `tests/ui`. Fully parallel; no retries locally, one on CI. Traces and screenshots are kept for failures.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| Fixtures              | [`fixtures/index.ts`](../fixtures/index.ts)                                                      | Extends Playwright's `test`. `createUser()` signs up a unique user through the API and, by default, opens a savings account with 10,000 (`initialBalance: null` for none, a number for that balance, `overrides` for custom fields). `loginAs(user)` puts the user's token in `localStorage` with an init script (before the app starts) and opens the dashboard, waiting until accounts and transactions have loaded with `200`. `openDashboardInNewContext(user)` does the same in a second, isolated browser context. `randomAmount(min, max)` gives a random whole amount and records it in the report. It also provides every page object and the `api` client. |

### Where expectations come from

The app has no specification, so every test is built on one of these:

| Basis           | Meaning                                                                                                                                                                                                    | A failure is       |
| --------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------ |
| **App**         | The app itself defines the behaviour: a validation message, a disabled button, an error it returns, a rule in its code.                                                                                    | A bug              |
| **Correctness** | True for any app of this kind with or without a spec: money is conserved, client input never causes a server error, data is shown as stored, a wrong password is rejected, user data is never run as code. | A bug              |
| **Contract**    | What the API does today, pinned as a regression guard (status codes and messages). Not a requirement; a change is flagged for review.                                                                      | A change to review |
| **Standard**    | A standard or common practice (WCAG 2.2 AA, OWASP ASVS, NIST, banking practice) that the app never committed to.                                                                                           | An observation     |

Known-issue tests carry the kind in their tags: **bug** (the app contradicts itself or basic correctness) or
**observation** (the expectation comes only from a standard or practice). 13 bugs and 9 observations are open; see the README for the list.
